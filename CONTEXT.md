# kmpow refresh: context handoff for another Claude session

Read this first in a new session; it captures the state and decisions so far.

## Project
- Personal site **kmpow.com**: React (CRA, MUI 7, react-router 6) frontend in `src/`, Django + DRF backend in `backend/` (apps: `blog`, `about`, `resume`, `contact`). Postgres in production, hosted on FreeBSD + Nginx.
- Work happens on branch **`refresh`** (not `main`).
- Goal of the refresh:
  1. Rebuild the home "galaxy" splash, where blog posts are stars and posts in the same category form constellations, as a deterministic grid.
  2. Clean up the codebase: no duplication, everything idempotent and reusable, real tests.

## How the user wants to work (important)
- **Before every code change, explain it in 2-3 sentences** (more only if needed). Make **one change at a time** so each edit can be approved knowingly.
- **Slow down and explain the whole problem before proposing fixes.** Avoid the XY problem: don't solve your own constraint and present it as theirs.
- Everything must be **composable, configurable and idempotent**.
- **DO NOT change any visual styling.** Every color, size, shadow and animation stays identical; styling will be discussed separately later. Exception: the galaxy is being redrawn in WebGL, so there it must *look* the same, checked side by side against the old DOM version.
- Keep comments minimal. The user trimmed docstrings and comments, so match the sparse style.
- Do the work in parts, in this order: **1. tests → 2. grid → 3. stars → 4. backend → 5. routes → …** Pause after each part so the user can run it.

## Decisions already made (don't re-ask)
- **Galaxy:** an endless wrapping grid (a torus of cells) plus a spherical "globe lens": stars toward the edges shrink, dim and curve "up and out". Panning is X/Y only, with no Z travel and no zoom.
- **Controls:** mouse/touch drag with inertia, wheel/trackpad, arrow keys. No idle drift.
- **Rendering: full WebGL** (decided 2026-11-05, replacing the DOM-only plan):
  - **One canvas.** Instanced star quads use a texture of the `StarOutlinedIcon` path. The glow, twinkle, lens and wrapping all happen in shaders. Constellation lines are drawn as quads.
  - **DOM overlay.** Only the tooltip is DOM, styled exactly as today.
  - **Picking.** Blog-star hover and click are hit-tested in JS with the lens function generated from the shader source (see shader pipeline), so clicks match what's drawn. Hover animates `scale(2)` with 0.3s ease-in-out, as today.
  - **Shader pipeline (one source).**
    - Shader math lives in `src/galaxy/shaders/*.glsl`. `scripts/shaders.mjs` uses the `glsl-transpiler` devDependency to write `*.generated.js` next to each file, exporting the GLSL text (`LENS_GLSL`) and a JS copy of its functions (`lens`). The generated files are gitignored.
    - Regenerated by `yarn start` (`--watch` mode runs alongside the dev server), `prebuild`, and the test image.
    - On a GLSL error, watch mode keeps the last good file and keeps watching.
  - **Hot swapping (Part 3 requirement).** The galaxy is the site's main component and will need a lot of visual tuning. The renderer must `module.hot.accept` the shader modules and `config.js`, and rebuild only the WebGL program and uniforms in place: keep the camera, the stars and the page, with no full reload. `module.hot` is absent in production builds.
  - **Accessibility and fallback.** A visually hidden `<nav>` lists a real link to every post. Without WebGL, that list (styled) is what's shown.
  - **Pure modules stay pure and tested in Jest.** Rendering is checked by eye or screenshots.
- **Blog posts come from Django admin only.** New posts get a grid cell automatically on save. `src/scripts/addStar.js`, `clearJson.js` and `src/static/stars.json` are dead code to delete.
- **Tests:**
  - All tests live in root `tests/`, not next to the code they test.
  - Backend tests use **pytest + pytest-django**.
  - Test configs are defined in **one Python file** (`tests/config.py`).
- **Seed data:** one source (`tests/seed/data/*.json`) with edge cases per component. Used for test fixtures and a local dev DB. Frontend mocks come from the same source, via API snapshots.
- **Docker:** tests run in Docker so they work on any OS, and the same command runs locally and in GitHub Actions on PRs.
- **Environment and secrets:**
  - Settings must **hard-fail** if env vars are missing; don't add defaults to `settings.py`.
  - **No real secrets** in tests or CI. Fake values live in the compose file.
  - Claude is blocked from writing `.env*` files by permission rules.
- **Repo hygiene:** migrations and `yarn.lock` should be committed (removed from `.gitignore`).

Migrations were **reset**: one fresh `0001_initial.py` per app (blog, about, contact, resume), generated from the current models. Prod's history differs (for example, resume had 0001–0004 on the server, never committed). On the **first deploy**, prod needs this one-time sync:
1. Back up with `pg_dump`.
2. Diff prod's schema (`pg_dump --schema-only`) against a test DB built from **only the `0001_initial` migrations** (`migrate <app> 0001` per app); later migrations like `blog/0002_blog_order` add things prod doesn't have yet. They must match.
3. Run `DELETE FROM django_migrations WHERE app IN ('blog','about','contact','resume')`.
4. Run `manage.py migrate --fake-initial`. This marks the `0001`s as applied without running them, then really runs everything after (e.g. adds `blog.order`, default 0).

### Bugs found (documented, not fixed)
- **Open question:** contact messages have no subject. Django saves the missing `subject` as `''` (not a bug), and `ContactPage.js` never sends one. Decide whether a subject is wanted.
- **React Router v7 future-flag warnings in tests:** enable `v7_startTransition` and `v7_relativeSplatPath` in the app router and `tests/frontend/support/render.js` together, in the routes part.
- **Stray props:** `BlogAccessories.js` passes `disableGutters`/`maxWidth` to a `Box` (they're `Container` props), so React warns about an unknown DOM attribute. Check `BlogPage.js:156` too.
- **Contact page:** status typo `"succes"` and a hardcoded `https://kmpow.com` POST URL in `src/ContactPage.js`.
- **Galaxy:** `Stars.js` crashes on a blog with `position: null`.
- **Prop mismatch:** `LoadingStars` passes `starCount`, but `TwinklyStars` expects `count`.
- **`order` field (backend FIXED 2026-11-06):** `Blog.order` now exists and the API returns posts ordered by `category, order, slug` (`Meta.ordering`, migration `blog/0002_blog_order`). Remaining: `ConstellationLines` and `BlogAccessories` still sort by `order` client-side (the field isn't in the API). Remove those sorts and use the API's order via `constellations.js`/`neighbors()`. Rule: the backend owns ordering, and the frontend never re-sorts.
- **Resume ties:** resume models order by `['order']` only, so items with the same `order` come back in no guaranteed order. Same root issue as blogs; add a unique tie-break field.
- **`ConstellationLines` logging:** it logs to the console on every render.
- **Unordered API:** the About list API sorts by `-updated_at` only (ties unordered). The blog list is fixed (see `order` above).

## Remaining plan (parts 2+)
**Open decision for Part 3:** the frontend grid needs `grid_col`/`grid_row`, which only arrive with the backend part. Either add a temporary percent→cell adapter or do the backend part first.

**Grid / galaxy (frontend, pure modules first, each with tests in `tests/frontend/`):**
- DONE `src/lib/random.js`: mulberry32 + `hash2(col, row, seed)`.
- DONE `src/galaxy/config.js`: every tuning value (cell size, density, star size, min gap, blog clear radius, lens strength, inertia, key step, click threshold, default galaxy).
- DONE `src/galaxy/grid.js`: `wrap`, `cellKey`, `cellCenter`, `torusDelta`, `worldSize`, `offsetFromCamera`. No `visibleCells`: the shader wraps, so nothing is computed per scroll.
- DONE `src/galaxy/background.js`: `blockedCells`, `starsForCell` (deterministic, bounded-retry min gap within a cell only), `backgroundStars` (the whole galaxy at once, uploaded to the GPU once).
- DONE `scripts/shaders.mjs` (see shader pipeline).
- DONE `src/galaxy/shaders/lens.glsl`, replacing the planned `projection.js`. Offset `d` maps to `R·sin(|d|/R)`, with `scale = cos(|d|/R)` and opacity following it (0 past a quarter turn, i.e. hidden). Identity at the center. `lensInvRadius` in `config.js` sets R = half the longer viewport side / strength. The pipeline is tested by `tests/frontend/shaders.test.js`.
- DONE `src/galaxy/camera.js`: pure `cameraStep(state, action, galaxy, options)`. Actions: drag-start/move/end (with `t`), wheel, key, tick (`dt`). Glide is integrated exactly (frame-rate independent); `click` is true only on the releasing step.
- DONE `src/galaxy/constellations.js`: `buildConstellations(blogs, galaxy, options)` → `{ groups, edges, neighbors }` in one pass, built once per blog list.
  - Groups keep the API's order (no sorting).
  - Edges are a start point plus the short-way torus delta, uploaded to the GPU once like the stars; the shader wraps them.
  - `neighbors` is a `Map` slug → `{ prev, next }`, used by `BlogAccessories`.
  - Reads `grid_col`/`grid_row` by default (`cellOf` option); unplaced posts get neighbors but no edges.
- **Galaxy (WebGL), replacing `Stars.js`:**
  - `useGalaxyControls` feeds `camera.js`.
  - `Galaxy.js` mounts the canvas, the tooltip overlay and the hidden link list.
  - The renderer owns shaders, buffers and the rAF loop. Per frame, JS only updates uniforms (camera, time, hover); React never re-renders.
  - Data is fetched once, and a resize only resizes the canvas.
  - **Fetch the blog list once for the whole app** (a small shared store or React context) and build `buildConstellations` from it once. Today `BlogAccessories` refetches every post on each post page just to find next/back. The galaxy, the lines and the arrows all read the same object. `BlogAccessories` switches to `neighbors` and drops its own sort.
  - WebGL library: not chosen yet (OGL recommended; three.js or react-three-fiber are the alternatives).
